# ShadowLab YARA Validation

This document records the current local YARA pack layout and the validation
checkpoint that ships with the release.

## Pack Sources

ShadowLab builds the local YARA layer from three sources:

| Source            | Path (relative to repo root)         | Required? |
|-------------------|--------------------------------------|-----------|
| ShadowLab rules   | `plugins/rules/`                     | Yes       |
| `rules-master`    | sibling clone next to repo, optional | No        |
| `signature-base`  | sibling clone next to repo, optional | No        |

Operators who want the full enterprise pack should clone the two community
repositories next to `shadowlab-detection-lab/` (not inside it):

```
parent-folder/
  shadowlab-detection-lab/
  rules-master/
  signature-base-master/
```

## Suppressed Rules

The following rules are excluded from the enterprise pack because they
produce too many false positives against real-world Windows binaries:

| Rule                   | Reason                                       |
|------------------------|----------------------------------------------|
| `RAT_PoetRATPython.yar`| Matches benign Python launchers              |
| `domain.yar`           | Matches every PE that references any domain  |

To add new suppressions, append the rule name to the policy file documented
in `services/antivirus/custom_yara.py`.

## Detection Flow

1. calculate file context and hash
2. query `YARAify` when configured
3. run local `enterprise` YARA if needed
4. combine local YARA, memory YARA, static PE context, antivirus provider context, and threat-intel context into the fused verdict
5. expose the result through process triage, antivirus workflow, response planning, telemetry, and desktop views

## Validation Inputs

Validation inputs should stay synthetic or lab-owned. Good candidates include:

- local ShadowLab validation samples
- controlled Inceptor-style payloads generated in an isolated lab
- benign PE files used for parser coverage
- test corpus entries in `config/detection_validation_corpus.json`

Do not validate against third-party or customer material unless you have explicit permission and a clean handling plan.

## Current Assessment

The current YARA state is a good fit for ShadowLab's Windows-focused detection and response workflow:

- local YARA is active
- `YARAify` remains the first external lookup when configured
- `Inceptor_*` and `Memory_*` rules stay high signal
- noisy utility rules no longer dominate verdicts
- compile health is clean
- results feed both process investigation and antivirus-style verdict workflows
